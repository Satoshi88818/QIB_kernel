FIX-N — isqrt Changelog/Annotation Cleanup

Status: Implemented, compiled, and test-validated (6/6 tests passing on Rust 1.75, cargo test --release, including a 1,000,000-value exhaustive sweep and a 200,000-sample deterministic random sweep). Lowest-effort item on the original review; done for completeness now that everything else is closed.

The inconsistency

The top-level project changelog read:

Fix E (RT): isqrt_u64 loop unrolled to fixed 32 iterations — isochronous timing guaranteed

But the actual implementation in qib-muk/src/quantum/fidelity.rs — and that same file's own doc comment — unrolls to exactly 6 iterations, and its Kani harness has always used #[kani::unwind(6)], never 32. The 32 figure belongs to a different fix: FIX-I's policy of #[kani::unwind(32)] as a conservative default for the genuinely bounded-but-not-unrolled loops in qib/src/routing/path_cost.rs. It was pasted into the wrong changelog line.

Changelog correction

- Fix E (RT): isqrt_u64 loop unrolled to fixed 32 iterations — isochronous timing guaranteed + Fix E (RT): isqrt_u64 loop unrolled to fixed 6 iterations — isochronous timing guaranteed - Fix I (Formal): #[kani::unwind(32)] annotations added to all bounded mathematical loops + Fix I (Formal): #[kani::unwind(32)] annotations added to the bounded loops in + path_cost.rs; the isqrt harness in fidelity.rs is annotation-free (see FIX-N — + it has no loop to bound in the first place) 

The decorative annotation

Separately: isqrt_u64_fixed has no loop. It's six unconditional, straight-line invocations of the newton!() macro. #[kani::unwind(N)] controls how many iterations of an actual loop/while/for the model checker explores before treating the rest as unreachable — there's no such construct here to bound. Kani would explore this function's one and only execution path identically whether the annotation says 6, 600, or is absent entirely. The annotation wasn't wrong, exactly, but it implied a formal guarantee ("termination bounded by N loop iterations") that doesn't apply to code that was never a loop. This patch removes it and replaces it with a comment explaining why, so a future reader doesn't have to rediscover that themselves. What the harness does meaningfully prove — result² ≤ n for all 64-bit inputs — is untouched.

Full source

The annotation was harmless, but it implied a formal //! guarantee ("termination bounded by N loop iterations") that doesn't //! apply to code that was never a loop to begin with — the *actual* //! guarantee here is unconditional termination by construction (no loop, //! no recursion, no unbounded recursion, full stop), which needs no //! `unwind` bound to state or prove. What the Kani harness *does* still meaningfully prove — and what this //! patch leaves completely unchanged — is the numerical correctness //! property `result² ≤ n` for all 64-bit inputs, which is a real, //! non-trivial claim about whether 6 fixed iterations are actually enough //! to converge for every possible seed, not just typical ones. #![allow(dead_code)] /// Integer square root — fixed 6-iteration Newton's method (FIX-E). /// /// 6 iterations are sufficient to converge for any 64-bit input when seeded /// with a leading-bit approximation. This function contains **no loop**: /// execution always performs exactly the same 6 Newton steps regardless of /// input, which is what makes it isochronous (constant-time) rather than /// data-dependent — the property FIX-E exists for. /// /// # Kani proof /// /// See `verify_isqrt_correct` below. It carries no `#[kani::unwind(N)]` /// annotation, deliberately: there is no loop in this function for such an /// annotation to bound. Termination is guaranteed unconditionally by the /// absence of any loop or recursion, not by a bounded-unwind argument. #[inline(always)] pub fn isqrt_u64_fixed(n: u64) -> u64 { if n == 0 { return 0; } // Seed: floor(sqrt(2^k)) where k = bit-length of n. let bits = 64 - n.leading_zeros() as u64; let mut x = 1u64 << ((bits + 1) / 2); // Exactly 6 unrolled Newton iterations (no loop, no data-dependent // branches that skip work — the `if` below only decides whether to // update `x`, not whether the division happens). macro_rules! See "Scope and honesty about validation" for what // this does and doesn't stand in for. for n in 1u64..=1_000_000 { let r = isqrt_u64_fixed(n); assert!(r.saturating_mul(r) <= n, "violated at n={n}: r={r}"); } } }

result_squared_never_exceeds_n_the_kani_harness_property — exhaustively checks result² ≤ n for every n from 1 to 1,000,000: the exact property verify_isqrt_correct (the Kani harness) asserts.

six_fixed_iterations_never_fall_short_across_a_wide_deterministic_sample — a fixed-seed xorshift64 sweep over 200,000 pseudo-random 64-bit values, comparing the 6-fixed-iteration result against an unbounded reference that iterates until actual convergence. Zero divergence.

Is 6 the right number, or just a round one?

To check whether 6 was chosen carefully rather than picked arbitrarily, the same reference-vs-fixed-iteration comparison was run at iteration counts 1 through 7, over 2,000,000 pseudo-random 64-bit values:

iterations=1: mismatches out of 2,000,000 = 1999903 iterations=2: mismatches out of 2,000,000 = 1970369 iterations=3: mismatches out of 2,000,000 = 1489113 iterations=4: mismatches out of 2,000,000 = 355240 iterations=5: mismatches out of 2,000,000 = 0 iterations=6: mismatches out of 2,000,000 = 0 iterations=7: mismatches out of 2,000,000 = 0 

5 iterations already converges correctly on this sample; 6 carries one iteration of margin beyond the empirically-sufficient count, rather than being either undersized or excessively conservative. (This is a sampled result, not exhaustive over all 2⁶⁴ inputs — an actual Kani run against verify_isqrt_correct would be the way to get an exhaustive answer; see below.)

Scope and honesty about validation

#[cfg(kani)] only activates under the Kani model-checker binary, never under plain rustc/cargo — so verify_isqrt_correct is inert in the cargo test run above by construction, exactly as it was before this patch. Kani itself isn't installed and isn't reachable over the network from this sandbox, so the actual formal proof was not re-run. What was validated instead is the same correctness property (result² ≤ n) via plain Rust tests: an exhaustive sweep over 1..1,000,000, a 200,000-sample pseudo-random sweep, and a targeted edge-case sweep. That's a strong empirical stand-in but explicitly not a proof over all 2⁶⁴ possible inputs the way Kani's harness is designed to be — flagging this the same way as FIX-K's TLA+ boundary and FIX-M's PyO3 boundary, rather than implying more rigor than what actually ran.

What did not change

isqrt_u64_fixed's logic is byte-for-byte identical — same seed computation, same 6 unrolled newton!() invocations, same result. This patch is documentation and annotation cleanup only; it does not touch behavior, and the tests above confirm that (comparing against the original file's own reference is exactly what matches_the_unbounded_reference_on_edge_cases and the 200,000-sample sweep do).

FIX-I's #[kani::unwind(32)] on path_cost.rs's two harnesses (verify_hop_cost_no_nan, verify_scarcity_term_non_negative) is unchanged — those genuinely involve Kani exploring kani::any()-typed inputs against real conditional logic, and 32 is a reasonable conservative default there. Only the isqrt harness's annotation, and the changelog line describing it, were in scope.

FIX-B's epsilon floor and FIX-A's m2 decay (the rest of fidelity.rs) are unrelated to this cleanup and untouched.
