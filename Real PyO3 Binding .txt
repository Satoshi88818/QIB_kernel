Real PyO3 Bindings — Closing the FIX-M / FIX-P Validation Boundary

Status: Implemented, compiled into a real Python extension module with maturin, installed into a real virtualenv, and validated with real pytest — 10/10 tests passing against genuine compiled bindings, not simulated or syntax-checked. This closes the one boundary both QIB_FIX-M_userspace_tests.md and QIB_FIX-P_mutex_poisoning_test.md explicitly flagged as unexecuted in their original sandbox sessions.

What this is

FIX-M (the digital-twin epsilon floor + correlation-group wiring) and FIX-P (the Mutex-poisoning test) were both validated by compiling their core Rust logic as plain libraries and testing it with cargo test. Both write-ups were explicit that the actual PyO3 extension module and the corrected Python test files were not built or run against a real interpreter — building that requires maturin, Python dev headers, and a matching ABI, which a follow-up feasibility check found were all actually available in this sandbox. This patch does that build for real.

The Rust logic itself is unchanged from FIX-M/FIX-P — the same epsilon floor, the same set_correlation_group, the same debug_poison_state_for_test mechanism — just wired into genuine #[pyclass]/#[pyfunction] bindings instead of plain Rust functions.

Environment setup

python3 -m venv .venv .venv/bin/pip install --upgrade pip maturin pytest 

python3-dev was already present (python3-config --includes resolves), so no system packages needed installing.

src/digital_twin.rs — FIX-M logic with real #[pyclass]/#[pymethods]:

//! Probabilistic digital twin — PyO3-exposed, real bindings. //! //! Carries FIX-A (EWMA), FIX-C (atomic DashMap entry mutation), FIX-M1 //! (epsilon floor on fidelity_std) and FIX-M2 (set_correlation_group, //! closing the correlation-group wiring gap) — see //! QIB_FIX-M_userspace_tests.md for the full history. This file adds the //! real `#[pyclass]`/`#[pyfunction]` wiring that patch's write-up described //! but could not compile in that sandbox session. use dashmap::DashMap; use once_cell::sync::Lazy; use pyo3::prelude::*; pub const UNCERTAINTY_SAFETY_TAX_THRESHOLD: f64 = 0.05; pub const CORRELATION_FAILURE_TRIGGER: u32 = 3; pub const CORRELATION_SAFETY_TAX_BOOST: f64 = 1.5; pub const EWMA_LR: f64 = 0.05; /// FIX-M1: a real floor, not `.max(0.0)`. pub const FIDELITY_VARIANCE_EPSILON: f64 = 1e-6; #[derive(Clone, Debug)] struct LinkStateInner { mean: f64, m2: f64, fidelity_std: f64, correlation_group_id: Option<u32>, } impl LinkStateInner { fn new() -> Self { Self { mean: 0.5, m2: 0.0, fidelity_std: FIDELITY_VARIANCE_EPSILON, correlation_group_id: None } } fn update(&mut self, obs: f64) { let delta1 = obs - self.mean; self.mean += EWMA_LR * delta1; let delta2 = obs - self.mean; self.m2 = (1.0 - EWMA_LR) * self.m2 + EWMA_LR * (delta1 * delta2); // FIX-M1 self.fidelity_std = self.m2.sqrt().max(FIDELITY_VARIANCE_EPSILON); } } static LINK_STATES: Lazy<DashMap<String, LinkStateInner>> = Lazy::new(DashMap::new); static GROUP_FAILURE_COUNTS: Lazy<DashMap<u32, u32>> = Lazy::new(DashMap::new); fn correlation_group_boost(link: &LinkStateInner) -> f64 { match link.correlation_group_id { Some(gid) => { let count = GROUP_FAILURE_COUNTS.get(&gid).map(|c| *c).unwrap_or(0); if count >= CORRELATION_FAILURE_TRIGGER { CORRELATION_SAFETY_TAX_BOOST } else { 1.0 } } None => 1.0, } } /// Python-visible snapshot of a link's state. Returned by /// `ProbabilisticDigitalTwin.get_link_state()`; read-only from Python. #[pyclass] pub struct LinkState { #[pyo3(get)] pub fidelity_std: f64, #[pyo3(get)] pub mean: f64, #[pyo3(get)] pub safety_tax: bool, #[pyo3(get)] pub correlation_group_id: Option<u32>, } #[pyclass] pub struct ProbabilisticDigitalTwin; #[pymethods] impl ProbabilisticDigitalTwin { #[new] fn new() -> Self { ProbabilisticDigitalTwin } /// FIX-C: atomic entry mutation — no read-modify-write race. fn observe(&self, link_id: &str, value: f64) { LINK_STATES.entry(link_id.to_string()).or_insert_with(LinkStateInner::new).update(value); } /// FIX-M2: the call that was missing entirely from the original API. fn set_correlation_group(&self, link_id: &str, group_id: u32) { LINK_STATES .entry(link_id.to_string()) .or_insert_with(LinkStateInner::new) .correlation_group_id = Some(group_id); } fn record_group_failure(&self, group_id: u32) { *GROUP_FAILURE_COUNTS.entry(group_id).or_insert(0) += 1; } fn get_link_state(&self, link_id: &str) -> Option<LinkState> { let link = LINK_STATES.get(link_id)?; let boost = correlation_group_boost(&link); Some(LinkState { fidelity_std: link.fidelity_std, mean: link.mean, safety_tax: link.fidelity_std > UNCERTAINTY_SAFETY_TAX_THRESHOLD || boost > 1.0, correlation_group_id: link.correlation_group_id, }) } } /// Test-only reset so pytest runs don't leak state between tests (the /// DashMaps are process-global static state, same as the real kernel/twin /// design — a test harness concern, not a product bug). #[pyfunction] pub fn _debug_reset_digital_twin() { LINK_STATES.clear(); GROUP_FAILURE_COUNTS.clear(); } pub fn register(py: Python<'_>, parent: &Bound<'_, PyModule>) -> PyResult<()> { let m = PyModule::new_bound(py, "digital_twin")?; m.add_class::<ProbabilisticDigitalTwin>()?; m.add_class::<LinkState>()?; m.add_function(wrap_pyfunction!(_debug_reset_digital_twin, &m)?)?; parent.add_submodule(&m)?; Ok(()) } 

src/calibration.rs — FIX-P logic with real #[pyfunction] bindings:

//! Telemetry fusion, circuit breaker, and learning-rate management — //! PyO3-exposed, real bindings. //! //! Carries FIX-D (poison-safe `lock_state!()`) and FIX-P //! (`_debug_poison_calibration_state`, a real poisoning hook for tests) — //! see QIB_FIX-P_mutex_poisoning_test.md for the full history. This file //! adds the real `#[pyfunction]` wiring that patch's write-up described but //! could not compile in that sandbox session. use once_cell::sync::Lazy; use pyo3::prelude::*; use std::sync::atomic::{AtomicBool, AtomicU64, Ordering}; use std::sync::Mutex; pub const LEARNING_RATE_NORMAL: f64 = 0.1; pub const BRIER_EVAL_WINDOW: usize = 50; pub const CRITICAL_DELTA_THRESHOLD: f64 = 0.3; pub const BRIER_Z_CONFIDENCE: f64 = 2.0; pub const CRITICAL_CONSECUTIVE_WINDOWS: u64 = 3; static AI_ROUTING_ENABLED: AtomicBool = AtomicBool::new(true); static CONSECUTIVE_CRITICAL_WINDOWS: AtomicU64 = AtomicU64::new(0); struct CalibrationState { learning_rate: f64, brier_window: Vec<(f64, f64)>, } static STATE: Lazy<Mutex<CalibrationState>> = Lazy::new(|| { Mutex::new(CalibrationState { learning_rate: LEARNING_RATE_NORMAL, brier_window: Vec::with_capacity(BRIER_EVAL_WINDOW) }) }); /// FIX-D: poison-safe lock. macro_rules! lock_state { () => { STATE.lock().unwrap_or_else(|poisoned| poisoned.into_inner()) }; } #[pyfunction] pub fn get_learning_rate() -> f64 { lock_state!().learning_rate } #[pyfunction] pub fn set_learning_rate(lr: f64) { lock_state!().learning_rate = lr.clamp(0.0, 1.0); } #[pyfunction] pub fn record_reality_delta(delta: f64) { let std_dev = { let state = lock_state!(); if state.brier_window.is_empty() { 1.0 } else { let sum: f64 = state.brier_window.iter().map(|(_, s)| s).sum(); sum / state.brier_window.len() as f64 } }; let z_score = if std_dev > 1e-9 { delta / std_dev } else { delta / CRITICAL_DELTA_THRESHOLD }; if z_score > BRIER_Z_CONFIDENCE { let windows = CONSECUTIVE_CRITICAL_WINDOWS.fetch_add(1, Ordering::SeqCst) + 1; if windows >= CRITICAL_CONSECUTIVE_WINDOWS { AI_ROUTING_ENABLED.store(false, Ordering::SeqCst); } } else { CONSECUTIVE_CRITICAL_WINDOWS.store(0, Ordering::SeqCst); } let mut state = lock_state!(); if state.brier_window.len() >= BRIER_EVAL_WINDOW { state.brier_window.remove(0); } state.brier_window.push((delta, std_dev)); } #[pyfunction] pub fn get_circuit_breaker_state() -> String { let state = lock_state!(); serde_json::json!({ "ai_routing_enabled": AI_ROUTING_ENABLED.load(Ordering::SeqCst), "consecutive_critical_windows": CONSECUTIVE_CRITICAL_WINDOWS.load(Ordering::SeqCst), "learning_rate": state.learning_rate, "brier_window_size": state.brier_window.len(), }) .to_string() } #[pyfunction] pub fn reset_circuit_breaker() { AI_ROUTING_ENABLED.store(true, Ordering::SeqCst); CONSECUTIVE_CRITICAL_WINDOWS.store(0, Ordering::SeqCst); let mut state = lock_state!(); state.brier_window.clear(); state.learning_rate = LEARNING_RATE_NORMAL; } /// FIX-P: genuinely poisons `STATE` by spawning a thread that locks it and /// panics while holding the guard, then joins (swallowing the resulting /// `JoinError` — the panic message is expected). Exposed to Python /// specifically so `test_calibration.py::TestMutexPoisoning` can trigger a /// *real* poisoning instead of merely calling the happy path and hoping /// that proves something about recovery. /// /// Never call this outside tests. In a production build this would be /// feature-gated (`#[cfg(feature = "debug-hooks")]`) rather than always /// compiled in, as noted in the FIX-P write-up; it's unconditional here /// only because this crate exists purely to validate the two patches. #[pyfunction] pub fn _debug_poison_calibration_state() { let _ = std::thread::spawn(|| { let _guard = STATE.lock().unwrap_or_else(|p| p.into_inner()); panic!("FIX-P test hook: deliberately poisoning STATE for testing"); }) .join(); } pub fn register(_py: Python<'_>, m: &Bound<'_, PyModule>) -> PyResult<()> { m.add_function(wrap_pyfunction!(get_learning_rate, m)?)?; m.add_function(wrap_pyfunction!(set_learning_rate, m)?)?; m.add_function(wrap_pyfunction!(record_reality_delta, m)?)?; m.add_function(wrap_pyfunction!(get_circuit_breaker_state, m)?)?; m.add_function(wrap_pyfunction!(reset_circuit_breaker, m)?)?; m.add_function(wrap_pyfunction!(_debug_poison_calibration_state, m)?)?; Ok(()) }

3. A real bug, found only by actually running pytest

The first pytest run genuinely failed — 3 of 10 tests:

FAILED tests/test_calibration.py::TestCorrelationGroups::test_group_failure_boosts_peer_safety_tax FAILED tests/test_calibration.py::TestCorrelationGroups::test_group_failure_on_a_different_group_does_not_affect_this_link FAILED tests/test_calibration.py::TestMutexPoisoning::test_record_reality_delta_survives_poisoning_mid_sequence 3 failed, 7 passed in 0.23s 

This was not a bug in FIX-M or FIX-P's logic. It was a bug in the test harness written for this patch: setup_function only fires before bare module-level test functions in pytest — it does not fire before methods inside test classes. Since every test here lives inside a class Test...:, the reset between tests was silently never running, and state (group failure counts, the Brier window) leaked from one test into the next. The fix was a one-line change to a proper @pytest.fixture(autouse=True), which does apply regardless of whether a test is a bare function or a class method:

@pytest.fixture(autouse=True) def _reset_shared_state(): digital_twin._debug_reset_digital_twin() qib.reset_circuit_breaker() yield 

This is exactly the kind of mistake that stays invisible in a write-up that only claims "the Python file was syntax-checked" — python3 -m py_compile would have passed on the broken version too, since the bug was in pytest fixture semantics, not syntax. It surfaced only because this patch actually ran the suite for real, which is the entire point of doing this work.

What this closes, and what's still out of scope

Closed: the specific gap both FIX-M and FIX-P flagged — "the actual PyO3 bindings ... were not compiled or run against a real Python interpreter" — is now false. They were, and the full test suite passes against them.

Still out of scope (unrelated to this patch):

This crate implements only the two functions' worth of surface area FIX-M and FIX-P needed (digital_twin and calibration), not the entire qib crate from the original document (routing, path_cost, the full AI module, etc.). Building the complete original crate would need the rest of its source, which was never fully available in this conversation.

_debug_poison_calibration_state and _debug_reset_digital_twin are compiled in unconditionally here, for simplicity, since this crate exists solely to validate these two patches. In the real crate, as FIX-P's write-up already noted, these belong behind a debug-hooks Cargo feature so they can never be reachable from a production build.

TLA+/TLC (FIX-K) and Kani (FIX-N) were separately confirmed feasible in this sandbox but are not part of this patch — this one was scoped to PyO3 specifically, per the request.
